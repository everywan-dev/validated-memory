1. Unresolved transaction counts alone do not gate without `--check`; plain

2. `_bootstrap` is no longer an ordinary-English spelling. Correct the

   `prepare_op` and `append_op` remain anti-reintroduction checks.
3. Replace the nonexistent prose name `PERMITTED_JOURNAL_SURFACE` with the

4. The declared-extension smoke test proves successful rendering and ID
   presence, not unchanged bytes or absent extension fields.
5. The no-artifact test asserts exit 0, no stderr and no pages; it does not
   establish avoided input reads or empty stdout.
6. The SVG safety fixture covers three diagram classes, not two; retain its
   non-vacuity argument.

Prose must state these limits rather than making stronger claims. No coverage
gap is closed by merely changing the sentence; those needing changed tests

## A — Shape: preserve the CLI seam

The tests exercise the same subprocess CLI interface as adopters. The local
helpers build fixture trees, histories and fault scenarios; their value is
locality of setup rather than a second implementation of runtime rules.
The journal's structural scanner is a distinct verification mechanism with
explicit limitations: receiver names, call shapes and allowlists are not
semantic proof of every filesystem write. The render golden checks one exact
fixture, while parsed-HTML assertions expose narrower properties.

Decision: retain these interfaces and file boundaries for T1. File length
alone does not establish a shallow module, and extracting fixtures or splitting
tests would add collection and ownership changes to a prose review. No new
abstraction or test seam is justified by the six documentary findings.
Existing coverage gaps remain open; shorter prose cannot close them.

### Retained verification limits

The reverse audit also keeps these distinctions close to their assertions:

- `test_a_created_file_records_its_postimage_and_both_stages` compares
  separately filtered op/path sequences, not their interleaving in history.
- `test_a_kill_at_after_transaction_leaves_the_path_untouched` observes exit
  70, absent target/history and a prepared transaction. It does not inspect
  fsync ordering. Race fixtures reach selected seams without proving a window's
  width or eliminating the re-read/publication race.
- The fault-variable comparison removes volatile history fields before
  comparison; the writer-shaped transaction fixture is manually assembled.
  A journal-text and transaction-count comparison is not a comparison of
  transaction-file bytes. A target-specific refusal is not proof of no writes
  anywhere in the adopter tree.
- The raw-write scanner checks a fixed vocabulary and recorder/mutation
  coexistence in a scope. Aliases, dynamic access and new idioms can evade it.
  The `O_EXCL` assertion remains labelled structural because a CLI fixture
  cannot select its syscall-sized race window.
- The render chain fixture is three levels deep and does not prove behavior
  at the recursion limit. The exact memory-page golden and separate byte/mtime
  assertions remain intact. Nested card ordering retains the reason for first
  versus last string-occurrence selection.

Literal exception descriptions and assertion messages are executable string
constants under this specification and remain unchanged even when they read
like prose. T1 does not claim a complete audit of those strings.

- Round 2, R2 (P2), preservation overclaims at two journal sites: the
  live-lock test preserves the lock inode/PID and asserts no journal or
  `.gitignore`, not an untouched whole tree. The gating-transaction test
  preserves the sole transaction ID and compares parsed history records,
  not transaction-file contents. The architect accepted both sites as one
  correction class; the programmer narrowed their docstrings and adjacent
  comments without changing executable nodes. R1 remains corrected.
