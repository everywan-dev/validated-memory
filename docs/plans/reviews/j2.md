# J2 — journal: the vocabulary

`journal/records.py`, `journal/paths.py`, `journal/operations.py`, and
`journal/durable.py`, which this unit created out of the first. Reviewed
2026-09-04 against `690da92`. The first unit reviewed under
[ADR 0010](../../adr/0010-code-prose-is-a-contract-a-constraint-or-a-verification-argument.md),
so every prose finding below names the class it assigned and every claim
about behaviour names what pins it.

## Axis A — shape

### A1. `Intention` promised more than it enforced. Applied (`a664597`).

ADR 0010 asks that a docstring enumerating illegal states be treated as a
question about the interface before it is treated as prose, and names this
one: 45 lines on nine fields and seven refusals. Asking it found the
contract false in three places. The docstring said `target` is `None` for
anything but a `LINK` and `directory` `False` for anything but a directory
`CREATE`; `__post_init__` checked neither. Constructible today, and
demonstrated at the interpreter before anything was changed:

- `REPLACE` with `directory=True` and no content (the content rule is
  skipped for a directory, and nothing said only a `CREATE` may be one),
- `LINK` with `directory=True`,
- `CREATE`/`REPLACE`/`APPEND` with a `target` no reader ever looks at.

Two answers were on the table: add three refusals, or make the states
unrepresentable. The second was taken. Construction is now five functions
-- `create_file`, `create_directory`, `replace_file`, `append_to_file`,
`link_to` -- each naming one mutation and fixing what the others would
carry, over a private `_Intention`. No factory takes `op` or `directory`;
none takes both a `target` and bytes; `create_file` and `create_directory`
do not take `expected` at all, so "a creation is never a no-op" stops being
a refusal and becomes the absence of a parameter.

The unit's public names went from 16 to 20, and its interface got smaller.
Those are not in tension: an interface is everything a caller must know to
use the module correctly, and that went from nine fields plus seven rules
to one signature of four to six parameters, none of which can disagree with
another. The facade's door did not widen at all -- `CREATE`, `APPEND`,
`LINK` and `Intention` left it as the four factories `init.py` reaches
entered it, 21 names before and after.

`__post_init__` keeps what naming the mutation cannot fix: an op outside
`INTENTION_OPS`, an unknown `durability`, a file mutation whose `content`
is None, a link whose `target` is None.

**Pinned by:** nothing new. The seven refusals were never reachable from
the CLI seam -- no caller builds an invalid intention -- and the three that
survive are still unreachable there. That is the same coverage gap the
shape change shrank rather than closed: four unpinnable refusals became
zero refusals plus a signature, which needs no pin.

### A2. `OBSERVE` was in the executable vocabulary to be refused twice. Applied (`ebc474e`).

An observation opens no transaction and is recorded at `committed` alone
(docs/design/2026-09-01-the-journal-core.md §4), and `Run.observe` owns it.
It was nonetheless in `INTENTION_OPS`, so an `Intention` could carry it,
and two modules paid: one of `Intention`'s seven refusals, and a
`ValueError` at the top of `Run._execute` that corrected the vocabulary at
the far end of the call. No caller ever built one.

`INTENTION_OPS` is now the four mutations; the construction is refused as
an unknown op; the executor's guard is gone with the state it guarded
against. In `transactions`, the observation test moved BEFORE the
membership test, because with `OBSERVE` out of the tuple the generic
refusal would have answered first and a hand-edited observation would have
been reported as an unknown operation.

**Pinned by:** `test_a_transaction_naming_an_operation_no_intention_carries_is_damaged`,
which asserts both damaged sentences verbatim; the reorder is what keeps
its second assertion true.

### A3. Atomic publication is not the record format's. Applied (`7a286ee`).

`install` and `fsync_directory` lived in `records.py`, which calls neither.
Their callers are `transactions` and `executor`, over transaction files,
parked preimages and adopter files -- none of them a record. The module
docstring listed what the module owns and did not mention them.

They move to `journal/durable.py`: a temporary published over a name, and
the barrier that makes the directory entry carrying that name survive a
power cut. Nothing there knows what a record is or where the adopter root
is.

Two alternatives were rejected. **Into `paths.py`** -- it already does I/O
and both callers already import it -- because `paths.py` rules on paths
under the adopter root while these two run over vault files no `authorise`
governs, and because `paths.py` is today one of the five modules
`test_every_write_in_the_package_goes_through_the_journal` proves write
nothing; moving them there would have bought a name at the cost of that
proof. **Leaving them and fixing the sentence** because it makes the
description true while leaving the seam wrong.

A two-function module is not shallow here: `install` hides an ordering
that is part of the correctness, and deleting the module puts `os.replace`
plus a directory fsync back into two callers at several sites.

### A4. `_` still marks nothing inside this package, and the count was low.

J1 deferred this to an ADR with ten names. Counted mechanically over the
package with `ast`, it is **twenty**, owned by four modules:
`transactions` 13, `paths` 5, `records` 1 (`_is_inside_path`, reached by
three modules), `fault` 1. J1 saw only the ones its own four files
imported. The decision is unchanged and still open; the evidence for it is
twice what `TODO.md` records.

### A5. `records.append` fsyncs the file and never its directory. Recorded, not fixed.

`install` exists because a rename is not durable until the directory entry
is, and `append` -- which creates `journal.jsonl` and
`.validated-memory/local.jsonl` on first use -- fsyncs the handle and stops
there. A power cut immediately after the first-ever append can lose the
directory entry, and with it a journal whose records were fsynced.

Bounded, not harmless: the transaction file is written through `install`,
so a lost journal is a recoverable transaction rather than a silent
divergence. Fixing it adds an fsync to a durability path, which is a
behaviour change with its own reasoning and not a review's to slip in.
Recorded in `TODO.md`.

## Axis B — prose

Five sentences deleted, all of the same kind: true, and no longer binding
any change someone could make today.

| Where | Sentence | Class it failed | Where it went |
|---|---|---|---|
| `records._check_types` | that a record carrying `"mode": true` reached `_restore` | incident | commit `74e02e1` |
| `records.read` | that a wrong type used to crash "one layer down" | incident | commit `74e02e1` |
| `paths.current_state` | that a broken symlink is "today's false `applied`" | incident | commit `74e02e1` |
| `paths._write_denied` | that a `.gitignore` at 0444 "was replaced in silence and handed back at 0644" | incident | commit `74e02e1` |
| `paths.authorise` | that before the fix only a write asked the resolved question | incident | commit `74e02e1` |

In every case the constraint the sentence existed to state was kept, in the
present tense: the `bool`/`int` exclusion (a modifier would "simplify" it
away), why `directory` is a kind at all, that `os.replace` needs permission
on the directory and not on the file, and why `observe` must ask
`authorise` too.

**Kept, and why.** `records.read`'s nine lines on `Path.exists()` are the
highest-value class in ADR 0010 -- the rejected alternative that looks
correct to the next reader -- and stay whole: `exists()` raises on a
permission denial, and `lstat` then `read_text` are two operations on a
name that can be repointed between them. `authorise`'s "what this does NOT
provide" stays for the same reason, and is a verification argument: it
says what the two checks do not prove.

**One reference resolved to nothing.** `paths.authorise` and
`docs/reference/journal.md` both sent a reader to "step 1b", a name that
exists only in a plan archived out of the repository -- the failure ADR 0010
gives as its example, surviving in two files because `test_docs_links`
checks path-shaped and `ADR NNNN` references and this was neither. Both now
name docs/design/2026-09-01-the-journal-core.md §6, which is in the
repository and says the same thing.

**Prose that grew, deliberately.** The unit is +1 496 prose bytes against
the baseline. Five factory docstrings and a module docstring are new prose
that replaced enforcement-by-paragraph with enforcement-by-signature, and
`install`'s docstring gained the admission that no test reaches its
ordering (ADR 0010's fourth rung). The bytes are the secondary figure, and
this is why.

## What the review of the review found

The branch went through this repository's two review steps before merging,
and the first of them found a defect in the unit's own prose (`3596137`).

**The unit wrote a false claim while removing four.** `_Intention`'s new
docstring said "a payload that disagrees with its op has no spelling here",
and three of the shapes `__post_init__` had stopped refusing -- a link
carrying content, a directory creation carrying content, a create expecting
anything but absent -- construct fine on the class itself. They are
unspellable through the five factories, which are the only door; the
sentence claimed it of the type. Reworded rather than re-enforced, for the
reason A2 gives: a package does not keep a refusal for a state its own door
cannot produce.

**Both new pins were weaker than their docstrings.** The layering pin
matched only relative imports, so `import validated_memory.journal.executor`
inside `paths.py` would have passed it; both absolute spellings are matched
now, and each was seen red. The schema pin asserted the refusal but not the
absence of a partial answer: it now asserts `journal: 0 record(s)`, the
count a reader serving what it had understood would print as 14, and its
docstring states what the seam cannot see -- the bad record is last, so
nothing proves the refusal precedes parsing the good lines.

### The second step: Codex LUNA (`gpt-5.6-luna`, xhigh)

Nine findings, over the branch as it stood before the fix above. Every one
was checked before being acted on; the two that mattered were reproduced.

**Accepted, and the reason.**

1. **A published mutation could still be smuggled past the vocabulary.**
   `Run.execute` reads fields off whatever it is handed, and A2 had deleted
   the guard that refused an observation. Measured, not argued: a foreign
   frozen dataclass with the same field names and `op="observe"` returned
   `Outcome(status='applied', ...)`, created the file and appended a
   `prepared`/`committed` observation -- a record pair nothing in this
   package writes. The fix is a type gate on `execute`, which is strictly
   wider than the guard it replaces: the old one refused one op, this
   refuses every object that is not an `_Intention`. Unpinned and
   unpinnable at the CLI seam, and the comment says so.
2. **`durable.py`'s own docstring was false about journals.** It said a
   journal line reaches the disk through these two calls; `records.append`
   opens for append and fsyncs the handle, and never calls either. The unit
   found that gap (A5) and then wrote prose denying it.
3. **`install` promised unconditional durability.** `fsync_directory` skips
   the barrier where a directory cannot be opened, so what the function
   promises without qualification is the atomicity, not the survival of the
   directory entry.
4. **The `0444` sentence was false in the present tense.** Rewriting the
   incident as a present-tense constraint (axis B, above) made it claim the
   mode still comes back 0644; `_publish` copies the target's mode onto the
   temporary before `install`, so it does not. The measurement is the
   design doc's and is now attributed there.
5. **Three modules read an intention's fields, not one.**
   `_open_transaction` copies them into the transaction file and
   `_postimage_state` reads three.
6. **The layering pin let the facade through.** `import
   validated_memory.journal` from inside a module closes the loop the pin
   exists to prevent, and was not matched. Now an offender from any module,
   seen red.
7. **Three counts in this file, the ledger and the plan disagreed with
   their own tables.** Corrected.

**Rejected.**

- **"`records.py` calls `durable` the module below it, but the facade lists
  it before."** Below is the layering sense -- a base module is beneath the
  ones that import it -- and the facade's order is the same order. Reworded
  to "the layer beneath this one" because the ambiguity was real, but the
  claim was not false.
- **"`JOURNAL_LAYERS` is duplicated in the test rather than read from the
  facade."** Deliberate, and the same shape as
  `PERMITTED_JOURNAL_EXPORTS`: a pin that derives its expectation from the
  file it is checking asserts nothing. The drift between the two is caught
  by the module-set assertion.
- **"The schema test does not pin that the refusal precedes parsing the
  good lines."** True, and already stated in the test's own docstring as
  what it does not pin.
