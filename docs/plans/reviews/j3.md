# J3 — journal: the write-ahead log and the lock

`journal/transactions.py` and `journal/lock.py`. Reviewed 2026-09-04 against
`bf28c6f`. The unit that inherited two deferrals — the underscore ADR from
J1 and J2, and the question of whether the transaction file has a module or
a bag of functions.

## Axis A — shape

### A1. `_` marked nothing inside the package. Decided and applied ([ADR 0011](../../adr/0011-inside-the-journal-package-an-underscore-means-no-other-module-may-depend-on-it.md)).

Deferred twice with a growing count: ten names in J1, twenty in J2,
**twenty-one** here — J2's own `_Intention` joined them when the executor
gained a type gate. Twelve were the write-ahead log's, which is why the
decision landed in this unit.

The ADR takes the option J1 called "drop the underscore", and the reason it
takes it is not the one this review was going to give. The draft argued that
the prefix was load-bearing for the text pin
(`test_no_module_outside_the_journal_reaches_past_the_executor`), which
scans the source of every module outside the package for names that never
occur in English prose. The challenge (Codex SOL) checked and refuted it:
`snake_case` is what makes those names scannable, not the prefix, and only
five of the twenty-one were in that list at all. Its second point finished
the alternative off — "`_` marks what the facade does not export" is already
false, since `now`, `record`, `append`, `read`, `current_state`,
`report_word` and `bootstrap` carry no underscore and are exported by
nothing.

185 occurrences, nine files, `ast` before and after: zero underscore names
cross a module line now. Three could not simply be un-prefixed and the ADR
says why: `fault_at`, `remove_transaction_file`, and the three
`VERDICT_*` verdicts.

**The measured effect on the ledger's `pub / priv` column is a change of
spelling, not of interface.** J3 shows +11 public and −10 private; nothing
became reachable from outside the package, which is what the facade's
`__all__` and two structural pins govern.

### A2. `own_directory` is a question about a path, not about a transaction. Applied.

The rule that a directory under the vault must be a real directory and not
a symlink somebody left there lived in the write-ahead log, and the executor
imported it out of there for the preimage store: two users, and the module
of one of them owned it. The same shape J2 found with `install`, and the
same answer — it moves to `paths.py`, whose charter is what is at one path
and what may be written to it. It reads and refuses; it writes nothing, so
the module the write pin proves writes nothing still does not.

### A3. The publish marker is the one write in the protocol with no guard. Recorded, not fixed.

`mark_published` reads the transaction file with
`json.loads(path.read_text())` and rewrites it, and `Run._execute` calls it
unwrapped, six lines below the comment explaining that the read beside it
was given a guard because it "raised out of `execute` and reached
`init.run`'s outer handler, which reports a whole-run journal failure over
one item".

The state stays correct if it raises: the bytes are published, no records
are appended, the transaction file is still `prepared`, and the next run's
recovery sees the postimage matching and completes it. What the user gets is
a traceback where every other failure in this protocol is a rendered
finding. Fixing it means deciding what an outcome says when the mutation
happened and the marker did not, which is a new shape and a behaviour
change, not a review's to slip in. Recorded in `TODO.md`.

### A4. `Resolution` does not validate and `Recovery` does. Deliberate, no change.

`Recovery.__post_init__` refuses an unknown action, an unknown problem, and
the both-or-neither case. `Resolution` accepts any string. The asymmetry is
right: `Recovery`'s two fields are set by `Run.recover` from a classifier
with six verdicts and the invariant is real, while a `Resolution`'s word is
derived by `cli.py` from `journal.RESOLUTIONS` itself, so no door can
produce another value. Adding the check would be a refusal for a state that
cannot be spelled — the rule J2 applied when it deleted the executor's
observation guard.

### A5. The transaction is a file with functions around it, not an object. Not changed, and why.

`transactions` offers the executor five verbs over one transaction —
`open_transaction`, `mark_published`, `abort_transaction`,
`remove_transaction_file`, `classify` — each taking `(root, id)` again. A
`Transaction` object would carry both and turn five calls into four methods.

Not done here, for two reasons that are about sequencing rather than taste.
The recovery path does not hold objects: it reads *files* into dicts
(`open_transactions`) and classifies those, so an object would need a second
constructor and a way to say which of the two it is — the mismatch is the
risk, in the one module whose failures are crash-shaped. And J4 is the
executor, the only caller that would gain: whether it wants an object is a
question its own review can answer with the executor in front of it. Noted
in the plan's log as a question J4 inherits.

## Axis B — prose

Three incidents deleted, every one of them already pinned:

| Where | Sentence | Pinned by |
|---|---|---|
| `open_transactions` | that a `UnicodeDecodeError` "escaped this function as a traceback out of `journal --check`" | `test_a_transaction_file_that_is_not_text_is_damaged_and_not_a_traceback` |
| `classify` | that "a file the adopter set to mode 000 came out of `journal --check` as a `PermissionError` traceback" | `test_an_unreadable_path_says_which_stage_its_transaction_reached` |
| `Recovery.appended` | that a caller "announced a recovery on every session start after the second" | `test_init_announces_a_recovery_only_when_the_history_gained_one` |

The constraint each existed to state stays, in the present tense: that
`read_text` raises a `ValueError` and not an `OSError`, that `current_state`
swallows `lstat` failures but not the digest read, and that `completed` has
two shapes that are not the same news.

Two comparisons with the implementation that came before go from `lock.py`
— "names the same file as before" and "rather than the read, the probe and
the unlink that spanned it before". Both were saying that today's code is
better than yesterday's, which binds nothing; the width of the window it
does buy stays.

**One docstring hid a refusal.** `_transaction_path` said "The file one
transaction lives in", and it `lstat`s the vault directory through
`_transactions_dir` and raises `JournalError` when something else stands
there. Five callers were told they were computing a path. Both docstrings
now say so, and say why the check lives in the path function: the name is
where the write is about to happen.

**One magic number became a decision.** The ten-second wait in
`Lock.__enter__` is now `LOCK_WAIT_SECONDS`, beside `STALE_LOCK_SECONDS`,
which had a paragraph while the wait had nothing. They are not the same kind
of number and the file now says which is which.
