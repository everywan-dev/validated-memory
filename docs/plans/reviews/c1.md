# C1 — the contract

Reviewed 2026-09-04 on `feature/review-c1-contract`, over `contract.py`
(662 LOC), `validate.py` (121), `extension.py` (254), `frontmatter.py` (205)
and `findings.py` (53): 1 295 LOC and, at 22 %, the lowest prose share of any
code unit in the review.

The four design questions went to Codex SOL (`gpt-5.6-sol`, high) before
anything was applied. **It refuted two of the four outright**, improved the
shape of a third beyond what this unit took, and on the fourth agreed with the
direction while rejecting the test I proposed. Every claim of its that was
acted on was checked first, by running something.

## Axis A — shape

### A1. The finding vocabulary had two sources. Applied (`84a0dec`).

`findings.py`'s own docstring says ERROR, WARNING and `Finding` live there
"rather than under either enforcement module". Three modules took them from
`contract` instead, which defines none of them and re-exported them only by
accident of importing them — and two of those three split one vocabulary
across two sources on adjacent lines:

    derive.py:19    from .contract import ERROR
    derive.py:20    from .findings import EXIT_ERROR, EXIT_OK, Finding

`validate`, `derive` and `render` now import all five names from `findings`.
`contract` still imports what it uses.

Codex's correction, which is right and is not applied: changing the consumers
does not remove the accidental re-export, because `contract.ERROR` is still
an attribute. Removing it means `contract` importing the module and
qualifying every use — about forty call sites for a name nobody reaches any
more. Not worth it, and recorded here so the next reader does not mistake
the commit for one that closed the hole.

### A2. The quoting rule read the parser's grammar across a module line. Applied (`4f618f2`).

The three rationale text values must be written quoted, and `parse` erases
the difference: it returns the same Python string for `reason: "x"` and
`reason: x`. So the rule read the raw source — and to read it, `contract`
carried a second tokenizer (indent, fences, comment-only lines), two
module-level regexes, and two comments saying those regexes mirror rules that
live in `frontmatter`, citing `_cut_comment` and `_tokenize` **by name across
a module line**.

`frontmatter.unquoted_values(text, block, keys)` now answers the lexical
question; `contract` keeps the rule — which block, which three names, why the
question is bounded to that block, and the finding. Inside `frontmatter` the
two grammars are its own and cite nothing across a line.

**The shape Codex proposed instead, and why this unit did not take it.** Its
answer was `parse_with_source(text) -> ParsedFrontmatter`: `data` as today
plus per-path metadata (line, `quoted`), with `parse` becoming
`parse_with_source(text).data` so the eight consumers are untouched. One
tokenization instead of two, and `contract` filtering exact paths. That is a
better division and it is recorded as the next step, not taken here, for two
reasons that are worth writing down:

- It gives the parser a notion of **path** (`rationale.options[0].label`) that
  it does not have today — its `_parse_block` returns plain dicts and lists.
  Serving one three-key rule by pushing an addressing vocabulary into the
  parser is the mirror of the leak being removed, and needs its own argument.
- It is not behaviour-preserving by construction. Today's scan flags those
  three names **anywhere inside the top-level block, at any depth**; a
  path lookup flags them only where the envelope says they belong. The two
  agree on every valid document and can disagree on a malformed one, so it is
  a change with its own tests, not a refactor.

What this unit took is the move: the same code, in the module that owns the
grammar. It leaves two traversals, both now inside `frontmatter`, where the
duplication is local and visible instead of cross-module.

### A3. The probe registry re-reads the configuration the same run already validated. Recorded, in `TODO.md`.

`validate.collect_and_validate` returns the extension, and its docstring says
why: "a caller that wanted it would otherwise have to load it a second time
and risk disagreeing with the validation that just ran". The one caller that
needs another part of the same file does exactly that. Measured on a scratch
tree by counting `Path.read_text` calls through a whole `probe` run:

    config reads: ['validated-memory.md', 'validated-memory.md']

`probe.run` calls `validate.gated_source`, which drops the extension, then
`extension.probes(Path())`, which reads and re-validates the whole
configuration a second time. It cannot be closed inside this unit: the probe
registry is not part of `Extension` (which carries only the declared fields),
`load` returns `None` when no `extension:` block is declared even though the
same file may carry `probes:`, and handing the registry to `probe` changes
`gated_source`'s signature, which `derive` shares. That is F1's ground.

### A4. Rejected: one `_is_non_empty_string` for the three that exist.

The same two-line predicate is defined identically in `contract.py`,
`extension.py` and — found by Codex, verified — `probes/git_ref.py:141`.
Centralising it was my proposal; the refutation is better than the proposal:

- It does not belong to `frontmatter`. "Non-empty" is a schema rule, not a
  syntactic one, and the parser is right to accept `""`.
- Putting it in `contract` widens the base contract's interface by a public
  name to save three lines, and would make `probes/git_ref.py` — a probe,
  the shape an adopter copies — import the contract to ask whether a string
  is blank.

Three local copies of an obvious two-line idiom is a local idiom, not a
shared vocabulary. Nothing has drifted between them; if one ever does, the
divergence is visible in the module that owns the rule it serves.

## Axis B — prose

### B1. A claim that named a path nothing reaches. Applied (`fc8a012`).

`extension.probes` said it re-validates the whole configuration "so a
malformed `validated-memory.md` raises `ExtensionError` the same way
regardless of which subcommand reads it first". **No subcommand reads it
first.** Measured:

    $ validated-memory probe          # id_prefix: "" in validated-memory.md
    ERROR: validated-memory.md: id_prefix: is not a non-empty string
    exit 1

That finding comes from `load`, through the validate gate `probe.run` runs
before asking for the registry. And `probe.run` has no handler for
`ExtensionError`, so a refusal from the second read would be a traceback
where every other configuration error is a finding. Class: **verification
argument** whose scenario is unreachable — it told a modifier that a
guarantee holds, and the guarantee protects nothing today. The docstring now
says what is true, including that a caller arriving without the gate gets a
traceback.

### B2. A claim nothing checked: the walk is iterative. Applied, seen red first (`2625351`).

`_check_supersession_cycles` carries "Iterative rather than recursive: a long
supersession chain would be a RecursionError, and a crash is not a finding."
Class: **constraint** — a modifier who rewrites the walk recursively breaks
it. The longest chain in the suite was three units, so nothing would have
caught that.

`test_a_supersession_chain_deeper_than_the_recursion_limit_is_still_checked`
writes 1 200 units in one chain (0.09 s) and asserts exit 0 with no
`RecursionError`. Seen red against a recursive descent over the same graph:

    RecursionError: maximum recursion depth exceeded
    [Previous line repeated 989 more times]

**The first version of the test passed against the recursive variant**, which
is the part worth keeping. A chain written so each unit supersedes the
*previous* id is entered by `sorted(edges)` in ascending order, so every
descent is one frame deep and nothing nests. The chain has to be written the
other way round — each unit superseding the **next** id — and the test says
so, because a later edit that "tidies" the direction would silently stop
pinning anything.

### B3. Claims already pinned, kept as constraints.

Each was checked against the test that fails when it stops being true, rather
than believed:

- **`_check_supersession_cycles`: "`_is_valid_id` first, always ... an
  unhashable one reaching `in declared` raises instead of being reported."**
  Pinned by `test_every_invalid_unit_gates_naming_unit_and_field`, row
  `id_not_a_string`, which declares `id:` as a list. Dropping the guard turns
  that row into `TypeError: unhashable type: 'list'` — verified by mutation.
- **The same docstring's "`probe` stops probing it, since only active units
  are probed"**, which is the reason a cycle gates instead of warning. True
  and pinned: measured 1 anchor probed across 1 unit on a two-unit
  supersession, and
  `tests/test_derive.py::test_only_active_units_are_probed_a_superseded_unit_keeps_its_last_verdict`
  fails if it stops being so.
- **`extension._config`: "a configuration with a malformed key stops every
  run, even a run of a subcommand that key does not concern."** Pinned by
  `test_a_malformed_config_stops_validation_naming_the_config`, whose table
  carries `probes_not_a_mapping` and `probe_command_empty` — two rows that
  gate a `validate` run, which never reads `probes`.
- **`BIDI_CONTROLS`: the bidirectional marks are deliberately absent.**
  Pinned by `test_further_bidi_marks_pass_clean_beside_the_rtl_guard` and
  `test_a_rationale_may_carry_right_to_left_text_and_bidi_marks`.

### B4. Recorded: runtime prose cites private names of other modules, and nothing pins it.

`test_docs_links.py` pins two classes of documentary reference inside a `.py`
— a `docs/….md` path and an `ADR NNNN` — which is ADR 0010's mechanical half.
A third class exists and nothing pins it: a comment naming a **private symbol
of another module**. Six in the runtime before this unit, five of them inside
the package (the sixth is `os._exit`, stdlib):

| where | cites |
|---|---|
| `contract.py` (two) | `frontmatter._cut_comment`, `frontmatter._tokenize` — **gone with A2** |
| `render.py:272` | `init._ensure_views` |
| `ignore.py:32` | `init._refusal` |
| `knowledge_view.py:218` | `corpus._group_history` |
| `corpus.py:338` | `verdicts._canonical` |

My proposal was a test that each such name still exists. Codex refuted it and
the refutation is the finding: existence does not make the sentence true, and
the test would turn an accidental private dependency into maintained
structure. **The honest rule is the opposite one — runtime prose does not
cite a private symbol belonging to another module of the package** — and it
is a rule about every module's prose, not this unit's, so it goes to
`TODO.md` as an ADR question. Its cost is the four remaining sites: three are
rewordings (state the precondition instead of naming who enforces it), and
`corpus` → `verdicts` is not, because there the private name marks a real
seam — two modules computing the same canonical JSON form, one of them
privately.

## Rejected, with the reason

- **A pin that the finding vocabulary has one source** (an AST scan of every
  module's `ImportFrom`). Rejected on Codex's argument: it fixes internal
  style without protecting behaviour, and "one source" would be a false
  description of what it checks. The honest formulation, if it is ever
  wanted, is "no consumer module imports ERROR, WARNING or `Finding` from
  `contract`".
- **Making `contract`'s ten module-local constants private.** Only three of
  its thirteen public names are used elsewhere (`EVIDENCE_STATES` by
  `corpus`, `BASE_FIELDS` by `extension`, `validate_documents` by
  `validate`). ADR 0011's second rule would mark the rest, but the ADR is
  scoped to the journal package and the enumerations are not internals: they
  *are* the contract's vocabulary, and `test_contract_docs.py` reads
  `BASE_FIELDS` out of the source **as text** to hold two shipped documents
  to it. Renaming would be churn against a published surface, for a rule this
  repository has not decided outside one package.
- **Deleting the comment in `validate.collect_and_validate` that repeats
  `ExtensionError`'s docstring.** It looked like S1's "the same contract
  written twice", and it is not: the two sentences bind different edits — the
  docstring says the loader raises rather than degrading, the comment says
  this caller must not degrade what it catches — and they sit in different
  files, so the comment is non-local information brought local, which is
  exactly what ADR 0010's third class is for.

1. **`parse_with_source`** (A2): whether the parser should carry the lexical
   facts it currently erases, at the cost of an addressing vocabulary it does
   not have. The next step after this unit's move, and a change with its own
   tests rather than a refactor.
2. **The configuration read twice in a `probe` run** (A3) — `TODO.md`, F1's
   ground, since closing it changes `gated_source`'s signature and the
   meaning of `load` returning `None`.
3. **Whether runtime prose may cite another module's private names** (B4) —
   `TODO.md` as an ADR question, with the four remaining sites and the one
   among them that is a seam rather than a sentence.
