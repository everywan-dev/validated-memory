# M1 — agent memory and corpus

Started 2026-09-05 from `a0e0ba5`, after F1, on
`feature/review-m1-memory`. Scope: `lint.py`, `memory.py`, and `corpus.py`;
only serializer ownership and its direct consumers cross that scope.

## Architect specification

Preserve CLI exit codes, finding text and order, source data, and rendered
bytes. Reduce repetitive and historical prose to concise contracts,
constraints, and verification arguments under ADR 0010. No byte quota,
runtime dependency, version change, or new abstraction without a caller.

### A1. One owner for canonical payload JSON

`corpus.canonical_payload` serialized JSON for display, while
`verdicts._canonical` serialized it for lookup and also handled the
absent-payload sentinel. The complete contracts were different, so merely
aliasing one function to the other would not preserve them.

Decision: `verdicts.canonical_payload(payload)` owns JSON serialization,
including the existing sorting, whitespace, escaping, and list-order rules.
`anchor_key` owns the separate absent-payload branch. Corpus and both view
consumers call the owner directly; no compatibility wrapper or re-export.
This closes the ownership question inherited from F1.

### A2. Keep parsing and policy separate

`memory` reads and resolves; `lint` applies policy. Their separation is
useful to the memory view and stays. Tiny field validators are not a reason
to introduce a generic validation framework.

The second frontmatter parse in `corpus.build` is accepted for this pass:
both parses consume the same in-memory document text, so this is redundant
computation, not a second filesystem snapshot. Removing it cleanly requires
reconsidering the parsed-document interface across validation and derivation.
No runtime speedup is claimed from prose reduction.

## Axis B — prose

- **Contracts:** validated corpus inputs; separate absent and recorded
  `unknown` verdicts; history in file order; anchors in declaration order;
  sorted presentation groups; raw-text headline extraction; active-only
  counts and navigation. Shorten repeated descriptions of the consumers.
- **Constraints:** filename identity including `.md`; ambiguity over all
  collected files, including unparseable ones; resolution before the
  self-supersession check; first-frontmatter-only source-description scan;
  direct-child source population and its symlink distinction. Preserve
  these rules in short local explanations.
- **Incorrect prose:** history grouping still named removed `service_view`;
  the module claimed all sequences were sorted; the log-total explanation
  confused all grouped records with the subset displayed for current
  anchors. Correct the claims, not the behavior.
- **History:** remove the dated source-import incident, the real-corpus
  anecdote, and repeated explanations of why shared readers were introduced.

## Independent challenge and architect rulings

Claude Code Opus, high effort, reviewed the proposals against public source

- Rejected the automatic YAML-date concern: this project's scalar parser

## Verification and acceptance

Three new tests in `tests/test_m1_contracts.py` exercise the CLI, without
importing implementation code:

| Contract | Assertion evidence |
| --- | --- |
| Nested mapping order does not identify an anchor | Reordered keys still give a current verdict, one history record, and no unprobed queue entry. |
| List order identifies an anchor; JSON formatting is stable | A reordered list does not match the recorded anchor; exact JSON literals, including ASCII escapes and spacing, appear in both queue and card. |
| Latest verdict and history follow file order | Reverse timestamps still select the last appended verdict and reverse-file-order history; legacy and orphan records remain in the total but outside the shown anchor's history. |

Existing `test_lint.py` assertions cover empty `.md` identity, ambiguity from
unparseable siblings, resolution before self-supersession, and the
first-frontmatter/direct-child source-description rule. Existing render
tests cover payload-null rejection, absent legacy payloads, active-only
counts and grouping, and recorded-unknown versus unprobed anchors.

The implementation preserves four contracts not yet isolated by a
discriminating CLI assertion: a heading inside a code fence, the declaration
order of multiple anchors, the payload tie-break in queue ordering, and
unit-id ordering within a map group. These are recorded coverage gaps, not
claims that membership tests prove ordering.

The programmer observed three characterization tests green on the baseline
and candidate, six generated HTML artifacts byte-identical, and seven
contrary-behavior mutants rejected: unsorted mapping keys, list normalization,
Unicode-format changes, compact JSON spacing, timestamp-sorted history,
timestamp-selected latest verdicts, and omitted legacy log totals. Every
isolated run explicitly selected its own package through `PYTHONPATH`.

Independent code review approved the implementation in round 1, checking
the saved differential artifacts and mutation failures and rerunning the
three new tests. The engineer returned PASS without edits: 656 tests passed,
six additional payload cases matched the baseline, output stayed stable
across hash seeds, and malformed-log unattended rendering retained the
existing pages with warning-only exit 0. Executable ASTs of `lint`, `memory`,
and the preceding journal prose correction matched the baseline after
excluding docstrings.

The architect accepted M1 on 2026-09-05 after reviewing the diff and this
evidence. Three tests were added; none were deleted or renamed. Versions,
dependencies, public behavior, and the remaining review order are unchanged.
