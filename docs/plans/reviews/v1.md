# V1 — the view stack

## Architect specification

Baseline: M1 plus its nonroot CI correction (`7b78e78`). Review the seven
modules listed in the active plan. Preserve executable ASTs after removing
docstrings, every generated HTML/CSS string, public behavior, and versions.
This is a context-size improvement, not a runtime-speed claim.

Keep the existing interfaces: orchestration builds opaque page strings,
knowledge cards and overview share a corpus, memory presentation does not
enforce lint, SVG owns diagrams, and HTML owns escaping and the shell.
Separate stylesheet constants are intentional. Do not add page classes,
forwarding wrappers, generic renderers, or a new parsing interface.

Condense prose under ADR 0010 while retaining these constraints:

- Text and attributes use different escaping; raw body/CSS inputs are trusted.
- Memory values are unvalidated; declared-name and relative-path anchor
  namespaces differ, while duplicate declared names remain duplicate IDs.
- Knowledge uses a validated DAG, an iterative walk and single-render links.
- History is append-ordered and windowed; totals include records not displayed.
- SVG geometry is integer-based; arbitrary text stays escaped and complete
  in the HTML fallback. Diagrams do not supply the only account of the data.
- Builds precede writes; publication is per artifact, unchanged files remain
  untouched, and unattended mode downgrades findings without bypassing gates.

Replace stale log-read and private-symbol references with current contracts.
Distinguish diagram-level titles from band titles carrying escaped timestamps;
do not call timestamp order chronological or list position a chosen-option
distinction. Remove obsolete style-development and anchor-collision histories.

Close four inherited M1 coverage gaps through CLI characterization tests:
raw heading inside a fence, anchor declaration order, canonical-payload queue
tie-break order, and unit-id order within a map group. Each must fail against
an isolated contrary behavior and pass against baseline and candidate. Do not
import runtime internals or ship mutation infrastructure.

## Findings and scope decisions

The initial independent reviews found two behavior defects outside this
byte-preserving change. Neither should be disguised by stronger prose:

- A directory occupying the PID-named temporary path causes cleanup's
  `unlink` to raise after the original write error. The real CLI reproduces
  a traceback. A separate correction needs explicit/unattended tests and
  a decision about primary versus cleanup findings; preserve existing files.
- Rationale SVG descriptions attribute `#n` only to text longer than 48
  characters, although more than eight short options also triggers numbering.
  Correcting the description changes output bytes and requires its own test.

Both are carried in local TODO rather than silently fixed in this refactor.
The known cleanup limitation must remain explicit in the shortened contract.

Existing verification gaps include recursion-limit-depth rendering, exact
SVG history-window order, concurrent publication and atomic-reader behavior,
per-diagram accessibility structure, exact fallback thresholds, and actual
keyboard/screen-reader/print/contrast behavior. Existing tests are not claimed
to prove these properties. Candidate evidence and final rulings follow below.

## Claude Code challenge and architect rulings

Claude Code Opus, high effort, challenged a generic design description with
tools disabled. Its suggestions are advisory, not executed verification.

- Accepted: mechanically compare ASTs with the already specified docstring
  exemption, compare output bytes, and report source/prose size for readers
  loading these modules into agent context. No byte threshold is introduced:
  ADR 0010 rejects quotas as a correctness signal.
- Accepted: raw insertion is trusted by caller provenance. Existing hostile
  input tests exercise escaping; the candidate must retain those call sites.
  State actual chosen-option distinctions: rounded/heavier border and text.
- Rejected as unsupported: duplicate declared names lack coverage. The
  existing CLI test explicitly asserts both entries retain the shared ID.
- Accepted as remaining work: exact 48/49 and 8/9 fallback boundaries need
  discriminating assertions. Do not expand this pass into all presentation
  coverage; the four inherited ordering/headline tests remain narrowly scoped.
- Accepted: cleanup can mask the primary failure; record the actual CLI
  symptom and require artifact preservation in its later correction. The
  numbered-label description is a concrete user-facing defect for a separate
  tested change, not something this prose pass can silently rewrite.
- Rejected as a new defect: per-artifact rather than cross-page atomicity is
  an explicit accepted limit. Building both pages first protects build
  failures, not a failure while publishing the second page.

Revisit module shape only when a real caller must compose another module's
implementation details; current callers do not justify a new interface.

## Candidate verification

Four tests were added in `tests/test_v1_contracts.py`; none were deleted or
renamed. They assert the exact headline or ordered sequence in the relevant
card, queue or map group, not merely membership. All four pass against the
baseline and candidate. Four isolated changes make the respective assertions
fail: skipping fenced headings, sorting declared anchors, removing the payload
tie-break, and reversing map IDs. Each CLI subprocess explicitly selects the
isolated package with an absolute `PYTHONPATH`.

All seven ASTs match after docstring removal, including every remaining
string constant. Sixteen baseline/candidate HTML artifact pairs match byte
for byte: the four new fixtures plus hostile all-diagram content, malformed
memory frontmatter, duplicate declared memory names and hostile memory text.
These comparisons do not assert untested browser behavior.

Runtime source fell from 62,466 to 39,573 characters and prose from 30,098 to
7,582, a 74.8% prose reduction. Runtime LOC fell from 1,405 to 1,021; the four
new tests add 84 LOC and 3,476 source characters. Net source reduction,
including tests, is 19,417 characters. Public/private names remain 12/23.
The [ledger](ledger.md) includes both savings and test cost.

The programmer's final full suite passed 661 tests in 70.73 seconds.
Independent code review approved round 1 after 95 focused tests; UserCare
passed its output review after 32 focused tests. Both independently checked
the seven ASTs and the sixteen saved HTML pairs. Neither edited the candidate.

The engineer returned PASS without edits: 661 tests passed in 67.98 seconds.
It reproduced the sixteen-pair comparison independently, then ran seven
additional cases against baseline and candidate with hash seeds 1, 42 and
777. Ten HTML artifact sets matched across those runs, covering history
windowing, legacy/null payloads, shared ancestors and malformed-input
fail-open behavior. The recorded browser/concurrency gaps remain unverified.

The architect reviewed the complete diff and evidence and ran the full suite:
661 passed in 68.86 seconds. V1 is accepted on 2026-09-05 for remote validation.
The published suite contains 658 tests; three additional tests are local to
this clone. No behavior, version, dependency or interface changed.
