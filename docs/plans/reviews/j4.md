# J4 — journal: the executor

Reviewed 2026-09-04 on `feature/review-j4-executor`, over
`validated_memory/journal/executor.py` (1 578 LOC, 53 % prose, two public
names). The unit inherits one question from J3 and answers it in a different
shape.

The design questions were put to Codex SOL (`gpt-5.6-sol`, high) before any
of them was applied. It refuted two of my four and raised a fifth that is
better than any of them; each of its claims was checked against the code
before being acted on, and one of its conclusions is refuted below in turn.

## Axis A — shape

### A1. `_bootstrap`: a name that said another module may depend on it. Applied.

ADR 0011 says an underscore is kept "for every name that is local to the
module that defines it". `bootstrap` had none, and nothing outside
`executor.py` depended on it: the facade exports `Run` alone and already
listed "the bootstrap" among the names the journal keeps to itself, and no
test names it. The one caller is `Run.__init__`.

Its four parameters were all defaulted, and the docstring justified the
defaults for callers it said in the same paragraph do not exist ("there is
none besides `Run`"). The one call site passes all four positionally, so
three branches that read a journal the caller had not passed, and one that
minted a run id of its own, were unreachable. Renamed, defaults dropped,
those four branches gone.

Codex proposed folding it into `Run` as a method instead. Rejected: it would
couple the opening write to a half-built `Run`, and the phase it names —
what happens before an invocation has an adoption id — is worth a function
of its own.

### A2. `_publish` was given a state it had to interpret. Applied.

`_publish` took the dict `current_state` returns and read exactly two fields
off it: `kind`, to choose between an exclusive creation and a replacement,
and `mode`, to give the temporary before the rename.

`_restore` has no such dict — it publishes the *preimage's* mode over
whatever a third party left at the path — so it invented one,
`{"kind": FILE, "mode": mode}`. The parameter is now `replacing_mode`: an
`int` to replace under that mode, `None` for "there is nothing there". That
is the whole of what publication was asking, and the synthetic dict has no
reason to exist.

Codex corrected my statement of the risk: a third field read from `actual`
would not fail silently, because `_restore` catches only `OSError` and a
`KeyError` would escape. Correct, and it makes the finding a shape finding
rather than a latent defect.

### A3. J3's inherited question, in the shape the executor gives it. Applied.

J3 left J4 to answer whether a transaction should be an object rather than
five functions taking `(root, id)`. With the executor in front of it, the
pair is not the problem. Two *dicts* are.

`classify` returns `(verdict, facts)` and its docstring said `facts` carried
"what the file and the filesystem said, so the caller neither re-reads nor
re-decides". Measured, all three of its callers re-read: the executor
reached into the raw `item` for `id`, `run`, `reason`, `preimage_blob`,
`prior_bytes` and `mode`, and `journal --check` for `id`. Two of those
re-did type checks `classify` had already made — it validates `mode`,
`prior_bytes` and `preimage_blob`, and refuses a transaction whose values
are wrong — so the executor was guarding against states `classify` cannot
return.

And `reason` was a key in **both** dicts with two meanings, read as each in
branches of `_recover_one` four lines apart: `facts["reason"]` is why a
transaction is damaged or its path unreadable; `item["reason"]` is what the
run that closed it `aborted` said.

Applied: `facts` carries every field, validated and with a settled type, and
the two reasons are `problem_reason` and `abort_reason`. `_complete` and
`_restore` no longer take the raw file, and no longer take a transaction id
either, since it is one of the facts. No object: a damaged file cannot
construct one without a second variant, which is J3's objection and it
stands.

`_survey` still reads the file directly, and its docstring now says why: it
runs at every `Run`, and classifying would `lstat` and digest each open
transaction's path to answer a question it does not ask.

### A4. `Run(root)` is not a constructor; it is an action. Recorded, not fixed.

Codex's fifth question, and the strongest shape finding in the unit.
Building a `Run` adopts the tree, so `journal --resolve` cannot simply build
one: `command.py` asks `missing_resolution` first, and `transactions.py`
carries that function for no other purpose. `_resolve_one` then repeats the
same "find the transaction by id" scan under the lock. A caller compensating
for its callee's constructor is the leak the axis exists to name.

Measured, not read: with the preflight removed, a virgin tree comes out of
the refusal holding both `journal.jsonl` and `.validated-memory/`.

But Codex's implied fix does not work, and this is where its answer is
refuted. It attributed the whole side effect to `_bootstrap`, as did all
three pieces of prose in the repository. A `Lock` entered on its own over an
empty directory leaves `.validated-memory/` behind by itself —
`Lock.__enter__` makes the parent of its lock file, and it runs before
`_bootstrap` is reached. So a lazier `_bootstrap` would remove half the
cause and leave a preflight that still has to exist.

Making `__init__` neither write nor lock is not available either: deciding
from what was read that no adoption id exists and then installing one is a
read-modify-write, and the lock is what stops two runs minting two ids for
one project.

What is applicable now is the prose (B6). The structural question — whether
reading a tree and adopting it should be two steps — needs `init.py` in
front of it, since that is the only caller wanting the adopting one. It goes
to `TODO.md` for **S1**.

### A5. `_execute` is two methods that share a scope. Named, not split.

Every one of the ten returns before `open_transaction` left nothing behind
— seven `_refused`, two refusals built before there is an `actual` to
report, and the no-op — and every one of the three after it closes a
transaction first, all three `_aborted`. The partition is exact at line 700,
with no exception, and the two helpers were already naming it.

Not extracted. The two halves share eight locals (`location`, `actual`,
`data`, `prior_bytes`, `postimage`, `blob`, `preimage_mode`, `intention`),
so an extraction would trade a 229-line linear method for a seven-value
handoff, which is a wider interface and not a deeper module. What went in is
one comment at the boundary stating the constraint: a refusal added below
that line which does not close its transaction leaves the path gated for
ever against a mutation that never happened.

### A6. `_refused` touches no `self`. Rejected.

It is the only method of `Run` that reads no attribute at all, so it is a
module-level function written as a method. Left alone: it sits beside
`_aborted`, its twin, which does need `self.root`, and moving one of the two
to module level would hide that they are the two halves of one rule.

### A7. `_complete`'s cache. Applied.

`histories` caches each journal's records across a recovery pass, and
`_resolve_one`, which completes exactly one transaction, was passing `{}`
positionally to fill the slot. Now optional.

## Axis B — prose

Seven sentences came out of `executor.py`, each replaced by the constraint
it existed to state. Three were history already pinned by a named test; one
was a contract claim that was false; one was a reference of a kind this
repository does not keep; one was a claim about behaviour that nothing
asserted, and it is now a test. The seventh is B6, below.

| Where | Sentence | Class | Pinned by |
|---|---|---|---|
| module docstring | recovery and resolution "share every one of those steps" with execution | contract, **false** | nothing — rewritten (B1) |
| `_survey` | "the permanent, uninvertible lie commit `4ce59a9` removed" | history | nothing — a bare commit hash (B2) |
| `_execute` | the re-read "raised out of `execute` and reached `init.run`'s outer handler" | behaviour, unpinned | now `test_a_path_that_stops_being_readable_before_publication_aborts` (B3) |
| `Run` | the older two-record protocol "is gone with its two methods" | history | nothing — the constraint it left stays |
| `_publish` | "this branch used to `mkdir(parents=True)`", and the `init` it broke | history | `test_a_creation_does_not_build_the_parent_the_same_run_refused_to_create` |
| `_recover_one` | "One sentence for both said `prepared` whichever it was" | history | `test_an_unreadable_path_says_which_stage_its_transaction_reached` |
| `_resolve_one` | "Closing with the observe alone left published bytes with no record" | history | `test_journal_resolve_over_a_published_transaction_keeps_its_record_pair` |

**B1. The module docstring's claim was measurable and false.** It said `Run`
is one class "because recovery and resolution share every one of those
steps" with execution, where the steps are the lock, path authorisation, the
expected-state check, the preimage, the transaction file, the publication
and its barriers, the mode, and both history records. Recovery shares the
lock, the record pair and the symlink-mode rule — three of nine. It
authorises no path, checks no expected state, opens no transaction file and
publishes nothing. Resolution shares those three and also `_park_preimage`,
`_publish` and `_unpublish`.

Codex caught two things here. The sentence is in the *module* docstring, not
in `Run`'s, which is where I had placed it; and my own count was too low,
because I had counted shared *helper calls* rather than shared *steps*, and
so had missed the lock and the mode rule. The rewritten paragraph names what
is shared and what is not, and it still justifies one class: a second class
would need `_record`, `_park_preimage`, `_publish` and `_unpublish` passed
to it or duplicated.

**B2. A commit hash is not a reference this repository keeps.** ADR 0010:
a documentary reference inside a `.py` is a versioned path or an
`ADR NNNN`, pinned by `test_docs_links.py`. `4ce59a9` was neither, and
nothing pinned it — the only bare commit hash in the whole runtime. The
constraint it decorated ("observing a path the plugin created as a fact
about the state adoption found is permanent and has no inverse") stays; the
pointer to where that was once fixed is in this unit's commit message
instead.

**B3. The claim that was not pinned is now a test.** `_execute`'s re-read
immediately before publication has two ways to refuse. A state that changed
was pinned; a path that can no longer be read was not — the branch existed
only in prose, in a comment describing the traceback it had replaced.

`test_a_path_that_stops_being_readable_before_publication_aborts` drives a
second process that takes read permission away inside the same window
`test_the_state_is_re_read_immediately_before_publishing` uses. **Seen red
first:** with the guard removed the run answers
`journal could not be opened: [Errno 13] Permission denied` — the whole-run
journal failure over one item, from `init.run`'s outer handler, exactly as
the comment described — and leaves the transaction open. 651 tests.

**B4 to B5.** The three remaining incidents are the last three rows above.
Each went to this unit's commit message; the constraint each existed to
state stays in the present tense.

**B6. A constraint that named half its cause.** Three places said the
`journal --resolve` preflight exists because `Run.__init__` bootstraps the
journal: `command.py`'s comment, `missing_resolution`'s docstring, and the
docstring of `test_resolving_an_id_nothing_carries_leaves_a_virgin_tree_virgin`.
Measured (A4), the lock is the other half. The distinction binds: a modifier
who made `_bootstrap` lazy would read those three sentences, conclude the
preflight was pointless and reintroduce half the defect. The test already
asserted both artifacts; only its prose named one cause.

## What this unit did not check

`PRIVATE_JOURNAL_NAMES` still lists `prepare_op` and `append_op`, which no
module defines — the two methods of the protocol `Run`'s docstring says is
gone. As a guard against reintroduction that is defensible; as a list a
reader trusts it is stale. It is a question about the test surface, so it
goes to **T1** rather than being answered here.

## Verification

Every claim above about behaviour was run, not read.

- 651 tests green at each commit (650 before this unit; +1 is B3).
  `ruff check` clean.
- A4's measurement: the CLI run twice on a virgin directory, with and
  without the preflight, and `Lock` entered alone over an empty directory to
  separate the two causes.
- B3 seen red with the guard removed, then restored.
- A3 gated by the four crash-seam tests and the damaged, diverged and
  unknown classification tests, which are what would catch a field silently
  changing type on the recovery path.
