# J1 — journal: reporting and fault seams

`journal/reconcile.py`, `journal/command.py`, `journal/fault.py`,
`journal/__init__.py`. Reviewed 2026-09-03 against `b80325e`. The pilot unit:
its purpose is as much to calibrate the two axes as to fix these four files.

## Axis A — shape

### A1. The reporting module reimplemented two pieces of the write-ahead log. Applied.

`command.py` imported eight private names from `transactions.py`, and two of
them were not borrowing a helper but re-stating a decision:

- **the unknown-id refusal.** `_run_resolve` asked `os.path.lexists` against
  `_transaction_path(...)`, then built a `Resolution` carrying
  `_transaction_artifact(...)` and `_no_such_transaction(...)` itself. The
  renderer knew where a transaction file lives and what the refusal says.
- **the recoverable word.** It mapped `_COMPLETE`/`_DISCARD`/`_REMOVE` to
  `RECOVERABLE` inline, so which internal verdicts count as recoverable was
  written down in the module that prints, one import away from the module
  that decides.

Both moved into `transactions.py` as `missing_resolution(root, id,
resolution)` and `report_word(verdict)`. `command.py` now asks whether there
is anything to resolve, not how a transaction is stored, and five of the
eight private imports are gone.

The cost is honest and in the ledger: +35 LOC and +929 prose bytes in J3
against −1 487 in J1. A module that owns a decision has to state it.

### A2. `_` does not mean module-private in this package. Deferred — ADR.

Ten underscore-prefixed names cross module lines inside `journal/`:
`_classify`, `_open_transactions`, `_transaction_path`,
`_transaction_artifact`, `_no_such_transaction`, `_resolves_below`,
`_well_formed_state`, `_COMPLETE`, `_DISCARD`, `_REMOVE` — each used by three
or four files. So the marker that should tell a reader "this is mine, do not
reach for it" carries no information inside the package, while still carrying
its usual meaning to anyone arriving from ordinary Python.

The package's own facade docstring already states a different convention —
"a module of this package is not a door either: it is imported whole, and
reached by attribute" — under which every module-level name is internal and
the underscore is redundant rather than wrong. Two coherent answers, and
picking one is a decision, not a cleanup:

1. drop the underscore from every cross-module name, so it means what it says
   and the facade stays the only door; or
2. write the convention down: inside this package `_` marks what the facade
   does not export, and crossing module lines with one is expected.

Not decided here. It touches four modules and ~40 call sites, and doing it
half-way is worse than either answer.

### A3. Two function-local imports that guard against nothing. Applied.

`command.py` imported `..findings` inside both `run` and `_run_resolve`. A
local import in this codebase reads as "there is a cycle here"; there is
none — `findings.py` imports nothing at all. Hoisted to module level.

### A4. The facade's claim about itself is true. Verified, no change.

`journal/__init__.py` says it exports "exactly the names `init.py` and
`cli.py` reach". Checked name by name: all 21 exports are reached, 19 by
`init.py` and 2 (`RESOLUTIONS`, `run`) by `cli.py`; none is reached only by a
test, and none is unused. The claim is pinned by nothing, which is worth
remembering when the comment ADR asks which assertions belong in a test — but
it is currently true.

## Axis B — prose

The rule already settled, in the user's words: a comment is not history. Only
that was applied here; how much contract prose a docstring may spend is what
the ADR decides, and these four files are the worked example for it.

Removed, in four places:

- `reconcile._state_of` — that raising used to end the whole pass, and that a
  broken symlink used to read as `applied` under `exists() or is_symlink()`.
  The constraints both comments existed to state are kept, in half the lines.
- `command.run` — that printing a hardcoded `0` "described a project with no
  history at all, which is a different and much worse fault than the one that
  happened".
- `command._run_resolve` — that an unknown id "used to leave a virgin tree
  adopted".
- `fault` — that "the two points that named the older `prepare_op`/`append_op`
  protocol went with it", and that the suite's only crash simulation before
  `_fault` was hand-editing an artifact.

Each of those sentences is true, and each belongs to the commit that made the
change. None of them tells a reader anything about how to change the code
safely today.

Also fixed while there: one docstring line in `command.run` ran to 120
characters, past the width every other line in the package keeps.

**Left standing:** 9 310 prose bytes, 59 % of these four files. The two
largest are `reconcile.reconcile` (a 49-line docstring for a 50-line
function) and the package facade (51 lines). Both are contract, both are
accurate, and both are longer than they need to be — the ADR's decision, not
this unit's.
